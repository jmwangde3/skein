# 最小项目档案契约（skein-init）

`kb/facts/projects/<仓名>.md` 给首次冷启动接手该子项目的 Agent 看，**接手时只读当前子项目那一份**。

## 规模与硬上限

- **目标体积**：1–2 KB（≤40 行）；**硬上限**：4 KB / 70 行。
- **范围**：建仓时，所有经用户确认纳入活跃范围的子项目均须具备最小档案；归档/无关目录不建档。

## 最小模板

```markdown
# <仓名>

- 状态：READY | PARTIAL
- 仓库：<相对工作区根路径，根仓写 .>
- 基线：<HEAD 短哈希> · <分支> · <clean|dirty>
- 巡检：`README.md#<hash8>` `package.json#<hash8>` `AGENTS.md#<hash8>`
- 建档：<YYYY-MM-DD HH:MM>

## 定位
<一句话说明解决什么问题> [源码/文档/推断]

## 入口
- `<路径>` — <作用> [源码/文档]

## 运行与验证
- `<命令>` — <来源>（未实测 / 已实测）

## 关键约束指针
- `AGENTS.md` — 改代码前必读

## 缺口
- <无，或写明影响开工的缺失项>
```

## 关键规则

1. **来源必标**：每句标明 `[源码]`、`[文档]` 或 `[推断]`，严禁把未验证的命令写成已验证。
2. **巡检看内容哈希**：对建档时实际读过的文件跑 `git -C <仓> hash-object -- <文件> | cut -c1-8`。日后刷新只重算这些哈希，未变则不刷。
3. **单仓读取预算**：建档累计读取 ≤8 KiB 文本，不抄源码片段、不抄整份 README、不记任务状态。
4. **冲突以现场为准**：档案只是导航，与 Git 现场不一致时以实际代码为准并顺手修正提交。
