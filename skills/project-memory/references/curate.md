# 低频整理

## 触发（任一命中）

- `INDEX.md` 超过 1000 tokens
- `facts/` 里出现互相矛盾的结论
- `journal/` 超过 200 行
- 同一个问题在三个以上文件里有不同答案

## 动作

1. **先出计划再动手。** 列出：要改哪些文件、每条移到哪、哪些需要人确认。计划本身写成 `proposals/<日期>-curate.md`
2. **旧结论标「已被替代」**，写清被哪条替代、什么时候替代的，再移进 `archive/`
3. **关键约束变更要人确认。** 涉及「能不能这么做」「边界在哪」的条文，不许自己改
4. **整理完立刻 commit**，一个整理一批，别攒着

## 禁止

- **不自动去重。** 两个文件写得像，可能是角度不同，删一个就丢了上下文
- **不自动合并。** 合并两份结论需要判断，判断不是脚本的活
- **不删 `journal/`。** 它是 append-only 的历史，折叠成摘要可以，删不行
- **不动 `proposals/` 里别人的建议。** 那是提交者的证据，由写者处理后标记状态

## 整理完的判据

`INDEX.md` 回到 1000 tokens 以内；`facts/` 里同一主题只有一个当前结论；`archive/` 里每条都能说清「被谁替代」。
