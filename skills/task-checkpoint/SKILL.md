# task-checkpoint

## 只做这一件事

把「现在做到哪、下一步做什么」写成一份陌生人也能读懂的检查点，并在长任务里续租。

**不做**：转派任务（`agent-handoff`）、合并分支（`agent-collab`）、整理知识库（`project-memory`）。

## 什么时候写

- 完成一个可验证的阶段结果
- 做了会推翻旧做法的决策
- 遇到阻塞、踩了坑
- **用户说「先到这 / 新开会话 / 明天继续 / 换会话」**
- 上下文被压缩前后（百分比看不出来，以宿主的压缩提示为准；50% 起留意）
- 要停下来（换天、换 agent、吃饭）

**不等用户提醒。** 长任务收尾时主动写；回复末尾带一行 `检查点：<路径>` 或 `检查点：无（原因）`，让用户能核对。

**同一个 agent 新开会话不写 handoff。** 检查点就是给下一轮的自己看的；handoff 只给另一个 agent 或另一台机器。用户说「写 handoff」但没点名交给谁 → 写检查点，回复里报路径；点名了接手方或明确要文件，才写 handoff。

**不写**：每条命令的流水账、「继续中」、源码里直接能看出来的东西。

**上下文被压缩后第一件事是重读检查点**，不是接着干。压缩会丢掉细节但留下「我记得做过」的错觉，这时最容易重复劳动。重读「已完成 / 不要重复 / 下一步」三节再决定动作。

## 写到哪

`<checkpoints>/<task_id>.md`，一任务一文件，每次覆盖为最新快照。

两个键都从**工作区根**的 `AGENTS.local.md` 读（从当前目录向上找到的第一个）：

- **`checkpoints`** —— 必需。缺了就报 `[HANDOFF_GAP]`，不要猜路径
- **`store`** —— 可选。有它且装了 `bd`，才做归属栅栏和续租；没有就只写文件。一个 agent 长期自己跑，不需要 Beads

任务 ID 用 `bd` 的 ID；没装 Beads 时自己起一个 `local-<子项目>-<日期>-<短名>`，同一任务始终用同一个。带上子项目名，是因为一个工作区里多个仓共用一个检查点目录，两个仓起同名短名会互相覆盖。

## 怎么写

**动笔前先读 `references/write.md`**，里面有完整的三层写入协议、检查点模板、`mode` 流转和写完自检。这里只留四条不许忘的：

1. **先读 rev 再写，rev 加 1，写完回读断言。** 文件里的 rev 比你上次读到的大，说明别人写过，先重读合并
2. **整份覆盖，不是追加。** 快照能一眼看懂；追加式日记要读到底才知道现状
3. **不写任务状态。** owner / status / 依赖实时读 `bd`，写进检查点就是制造第二份真相
4. **`rev` 是自检不是锁。** 它拦得住守规矩的写者，拦不住直接覆盖文件的人；也不要把它当跨进程互斥
