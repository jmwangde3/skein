## `--adopt-routes`：把已有子路由收编进工作区

**解决什么**

工作区里已经有好几个各自建过库的子项目，每个子目录都有一份 `AGENTS.local.md`。技能从当前目录向上找，第一个命中的是子目录那份，永远进不了父级的新库。

**大概怎么做**

建库脚本加一个开关 `--adopt-routes`，带上它时：

1. 把扫到的子路由备份到 `<数据家>/<工作区名>/backups/legacy-routes/<相对路径>`
2. 全部备份成功之后，才删除原子路由
3. 删掉的子目录从此继承父级路由

**只搬路由文件，不动 `store` / `checkpoints` / `kb`。** 旧任务不会自动出现在新库里；想找旧任务，按备份文件里记的路径去翻。所以这是「切换」，不是「合并」。

**为什么先不做**

- 目前没有这种工作区，现有部署都是单路由
- 这是会让人误以为「旧任务丢了」的操作，必须在用户明确知情时执行
- 默认拒绝已经挡住了误伤，缺的只是「一次收编多个」的便利

**什么条件下再做**

真出现「三个以上已建库的子项目要并进一个工作区」，或者有人手工删路由删错了。

**现在的行为**

扫到子路由就停下、列清单，交给用户决定（保留独立 / 手工处理 / 以后用这个开关）。
