# 交接失败恢复矩阵

按**现场特征**查表，不按报错文本查。报错信息会变，现场特征不会。

| # | 异常 | 现场特征 | 强制动作 |
|---|---|---|---|
| 1 | 检查点已写，任务释放失败 | `unclaim` 报错，`show` 仍显示 A 是 assignee | A 活着：先原样重试一次，仍失败就 `show` 核状态，**成功前严禁通知 B**；状态解释不了报 `[HANDOFF_GAP]`。A 已崩：B 等 `lease_expires_at` 过期后 `bd -C "$B" reclaim` 接管 |
| 2 | 任务已释放，接手方领取失败 | `unclaim` 成功（assignee 为空），B 的 `--claim` 报错 | 不需要召回 A。任意合法接手方重查 `show` 确认 assignee 为空，重读最新检查点后重新 `--claim`；若已被第三方抢走，按正常占用处理 |
| 3 | 任务 ID 与检查点对不上 | 检查点 YAML 的 `task_id` 与手上的 `<id>` 不同 | **立即停手**。严禁静默把 `task_id` 改成一致。贴出检查点头部与 `show` 输出，报 `[HANDOFF_GAP]` 交人工裁决 |
| 4 | `checkpoint_rev` 比预期旧 | 读到的 rev 小于本 agent 上次写入的值 | **拒绝写入**。重读检查点全文 + `git status --short` + `git log -n 5`，判断是工作树被回滚还是检查点被覆盖。确认真实进度、合并内容后，用「当前读到的 rev + 1」重走三层协议 |
| 5 | 检查点指向的 worktree / 文件不存在 | `worktree` 目录不存在，或 `dirty_files` / `untracked_files` 里的文件在磁盘上找不到 | 在检查点「未验证与阻塞」里标**现场缺失**。前任可联系就要 commit SHA 或 `.patch`；联系不上就按当前 HEAD 重新评估缺失工作量，写明「原现场已丢失」后重排步骤 |

## 两条通用规则

**不许盲目重试。** 同一个动作失败两次，就换成读状态（`show` / `status` / `log`），不要再按原样敲第三遍。

**不许自动清理。** 任何 `git clean`、`checkout --`、`reset --hard` 之前先把 `git status --short` 全文留档。未跟踪文件删了没有 git 能救。

## 三个容易忽略的细节

**`reclaim` 不是「只回收我这条」。** 它回收库里所有过期租约。执行后必须 `show` 确认目标任务现在归谁，别假设结果是自己。

**`heartbeat` 失败等于租约可能已丢。** 先 `show` 核归属，确认前不要继续写检查点。别用「刚才还能写」推断现在还归我。

**整份重写用同目录临时文件再替换**（`> file.tmp && mv file.tmp file`），避免写到一半留下半截文件。但文件替换不是跨进程 CAS 锁，别把它当原子保证。
