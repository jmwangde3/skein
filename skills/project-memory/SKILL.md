# project-memory

## 只做这一件事

在**不整份加载**的前提下，从知识库拿到需要的那一段；把新产生的事实与决策写回去；给一个已有项目写一份能让陌生人接手的档案。

**不做**：不碰任务状态（Beads）、不碰检查点（`task-checkpoint`）、不做语义自动合并。

**建库、接入工作区、项目建档都归这一个技能。** 别的技能只读库，不建库；`install.sh` 只复制技能，不碰项目目录。实际动作由技能目录里的 `scripts/init.sh` 完成——技能调用它，用户也可以直接跑它，但**只跑脚本得不到项目档案**（见 `references/init.md`）。

## 规则只有四层

建了库的工作区，规则只能落在这四个地方。**不许新建第五个规则文件**（`RULES.md`、`CONVENTIONS.md`、`NOTES.md` 这类一律不认）。

| 层 | 落地 | 管什么 | 进 Git |
|---|---|---|---|
| a 全局 | `~/.workbuddy/agent-memory-snippet.md`（主本）→ 各客户端 `AGENTS.md` | 语言、编码习惯、安全边界、跨工作区通用 | 各客户端管 |
| b 工作区 | `<工作区>/AGENTS.md` | 这个工作区怎么干活：技术栈、发布闸门、禁止事项 | 进 |
| c 库 | `<工作区>/AGENTS.local.md` | 库路径与本工作区例外 | 不进（本机私有） |
| d 项目 | `<仓>/AGENTS.md` | 单个仓的约束 | 进各自仓 |

「如果有」：b 和 d 可以没有；a 各客户端不同；c 建库后必有。

**a 层不直接改客户端文件。** 主本是 snippet，改完跑 `H:\AI工作区\agent-workspace-bridge\sync-agent-memory.ps1 -Update` 分发；直接改 `~/.codex/AGENTS.md` 会在下次同步时被覆盖。`MEMORY.md` 是跨项目记忆索引，不是规则的副本。

**c 层只放路径和例外。** 接手顺序、写回位置、检索阶梯都是流程，归技能；`<kb>/INDEX.md` 是可重建的索引，不算规则层。

**技能正文不算一层。** 技能管「怎么做」——检索阶梯、检查点模板、写入协议，跨工作区不变。这四层管「这个项目允许什么、禁止什么」，每个工作区不同。

### 新规则往哪写

1. **先判它是不是规则**：三个月后还有用吗？只对这次任务有用 → 检查点，不是规则
2. **再判它跨不跨项目**：
   - 跨所有工作区 → a
   - 只在这个工作区 → b
   - 只是库的用法 → c
   - 只在一个仓 → d
3. **写之前先搜四层**：`grep -rn "<关键词>"` 四个位置。有旧的，合并或删掉，不要两份
4. **同一句话只出现在一层**：b 里不要重复 c 的路径，c 里不要重复 a 的编码规则

**写规则时顺手清旧的。** 新规则和旧条目矛盾，改旧条目或删掉；只在末尾追加不改前面，等于给自己埋冲突。

## 库在哪：向上找作用域

```bash
SCOPE=""
d="$(pwd -P)"
while :; do
  if [ -f "$d/AGENTS.local.md" ]; then SCOPE="$d"; break; fi
  p="$(dirname "$d")"
  if [ "$p" = "$d" ]; then break; fi
  d="$p"
done
[ -n "$SCOPE" ] || { echo "[HANDOFF_GAP] 没找到 AGENTS.local.md（应在工作区根）"; exit 1; }
kv() { sed -n "s/^$1:[[:space:]]*//p" "$SCOPE/AGENTS.local.md" | head -n 1 | tr -d '\r'; }
KB="$(kv kb)"
[ -n "$KB" ] || { echo "[HANDOFF_GAP] 缺 kb 键"; exit 1; }
```

**作用域 = 一个目录，可以包含多个 git 仓。** 一个工作区一套库，不是一仓一套。子目录里再放 `AGENTS.local.md` 会遮住工作区那份。

## 检索阶梯：从便宜到贵，命中就停

| 级 | 动作 | 用在 |
|---|---|---|
| 0 | 读**当前仓那一份** `facts/projects/<仓名>.md` | 接手一个已有项目，先知道它是什么、从哪进、怎么跑 |
| 1 | 读 `INDEX.md` + `current.md` | 定位到 1–2 个文件 |
| 2 | `es -path "$KB" "<文件名片段>" -n 20 -export-json <tmp>` | 只记得文件名、不记得内容 |
| 3 | `rg -n "<词>" INDEX.md current.md facts decisions runbooks` | 已知术语、函数名、错误码 |
| 4 | `qmd search "<词>" -c skein-kb -n 5` | 换词、跨文件（**50 篇以上才开**） |
| 5 | `qmd get <file>:<from>:<count>` | 回读命中段 |
| 6 | `qmd vsearch` | 概念模糊、前几级全漏 |

**禁止**：开局 `cat` 整个文件、把 `archive/` 纳入常规检索、一次返回几十条、**把 `projects/` 下所有档案一起读**。

第 0 级只读**当前涉及的那一个仓**。跨仓任务才按实际涉及数量读，读之前先确认任务真的跨仓。档案本身也有上限（4 KB / 70 行），超了就是写多了。

细节与坑（`es` 的 GBK 问题、`qmd` 的 mask 铁律、工具缺失时怎么降级）在 `references/search.md`。

## 写入：全库单写者

同一时刻只有一个 agent 直接写 `kb/`。**并行开工前由发起方点名指定写者**，写者写满整个并行期；交接时写者身份随检查点一起交给下一个人。**主动接管只在旧写者确认停止后才转移写权**——改派任务不会让 A 停下笔。没点名就等于没写者，此时谁也不许直接改库。

其他人写 `proposals/`，文件名带上子项目，免得两个仓用同一个主题撞车：

```
proposals/<日期>-<子项目>-<主题>.md
改哪个文件：
改什么：
为什么：
证据：
```

由写者合并，写完立刻 commit。

**为什么必须这样**：Git 只报「同段冲突」。改不同文件不冲突；改同一文件不同行自动合并且不报错——语义覆盖会静默发生，事后查不出来。

## 五个 references，按需读

| 文件 | 什么时候读 |
|---|---|
| `references/init.md` | **接入一个新工作区、建库**（唯一入口，调 `scripts/init.sh`，含逐仓建档流程） |
| `references/brief.md` | **写或刷新项目档案**：模板、字段来源、4 KB 上限、黑名单、中断恢复 |
| `references/search.md` | 要完整命令、`es` 乱码、`qmd` mask 报错、判断该不该开 QMD |
| `references/migration.md` | 旧库迁进来 |
| `references/curate.md` | `INDEX.md` 超 1000 tokens、`facts/` 出现矛盾、`journal/` 超 200 行 |

规则体检用 `scripts/check-rules.sh <工作区根>`：只读，查 c 层键、b→c 兜底、第五个规则文件（含文件名带 `rule` / `规则` 的）、忽略规则、b/c 重复、a 层是否分发。

## 完成标志

- 检索：能贴出命中的原文片段与文件路径，不是「我记得有」
- 写回：`git log` 里有一条对应提交，`INDEX.md` 能定位到新文件
- 建库：按 `references/init.md` 的验收表逐项过一遍（含 `facts/workspace-map.md` 与 `facts/projects/INDEX.md`），全绿才算完成
- 建档：**目标仓**那行是 `READY`（五条准入全过）；每份档案都标了来源（源码 / 文档 / 推断），缺口写清而不是留空。没被选中的仓保持 `TODO` 是正常状态
